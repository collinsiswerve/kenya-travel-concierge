UPDATING THE SITE
Edit the source files listed in README.md, then rebuild and check:

python3 scripts/build.py
python3 scripts/check.py
python3 scripts/check_seo.py
node --check assets/app.js

Commit the updated source files, public files and matching dist copy to main.
GitHub Pages publishes the top-level index.html and its neighbouring folders.
If uploading files through GitHub, keep their paths and upload the contents of
this repository, rather than a ZIP or an extra outer folder. GitHub limits
browser uploads to 100 files per batch, so larger updates need several batches.

PAGES SETTINGS
Settings > Pages > Build and deployment:

Source: Deploy from a branch
Branch: main
Folder: /(root)

The .nojekyll file keeps the site as static HTML. No custom build workflow is
needed. Leave the custom domain empty while using the github.io address.

CHECKING THE DEPLOYMENT
The Actions tab shows the pages build and deployment status. Wait for success,
then visit the website. Publishing may take several minutes. If an old page
remains visible, refresh it with Ctrl+F5. A failed run has details in its logs.

MAIN FILES AND FOLDERS
index.html    Homepage.
assets/       Images, fonts, styles and JavaScript.
services/     Service catalogue and ten service pages.
contact/      WhatsApp and email enquiry form.
privacy/      Privacy Policy.
terms/        Terms & Conditions.
404.html      Missing-page fallback.
dist/         Matching built copy, including editable styles and JavaScript.
data/         Service content, business details, social links and legal text.
scripts/      Build and checking scripts.
docs/         Image notes, preview and search visibility notes.

The website does not store enquiries or take payments online. Visitors review
and send their own prepared message using WhatsApp or their email app.
